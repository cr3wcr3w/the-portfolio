## Database Normalization
- Database normalization is a process used to organize a relational database to reduce redundancy and improve data integrity.
- It involves dividing large tables into smaller ones and defining relationships between them.

---

## First Normal Form (1NF)
**Description:** 
Ensures that each table cell contains only a single value and eliminates repeating groups.

- Each column contains atomic (single) values
- Each column contains values of a single domain/type
- No lists or multiple values in one cell
- Each row must be uniquely identifiable (primary key)

**Example (Before 1NF):**
| StudentID | Name  | Phone Numbers |
|-----------|-------|---------------|
| 1         | John  | 12345, 67890  |

**Problem:**
- Multiple values in one column (not atomic)

**1NF Solution:**
| StudentID | Name  | Phone Number |
|-----------|-------|--------------|
| 1         | John  | 12345        |
| 1         | John  | 67890        |

---

## Second Normal Form (2NF)
**Description:** 
Removes partial dependencies so that all non-key attributes depend on the full primary key.

- All non-key attributes depend on the entire primary key
- Remove partial dependencies (only for composite keys)

**Example (Before 2NF):**
| OrderID | ProductID | ProductName |
|---------|----------|-------------|
| 1       | 101      | Laptop      |

**Problem:**
- ProductName depends only on ProductID, not full key

**2NF Solution:**

**Orders Table:**
| OrderID | ProductID |
|---------|----------|
| 1       | 101      |

**Products Table:**
| ProductID | ProductName |
|-----------|-------------|
| 101       | Laptop      |

---

## Third Normal Form (3NF)
**Description:** 
Removes transitive dependencies so that non-key attributes do not depend on other non-key attributes.

- No transitive dependencies
- Non-key attributes depend only on the primary key

**Example (Before 3NF):**
| StudentID | Name  | Major | DepartmentHead |
|-----------|-------|-------|----------------|
| 1         | Alice | CS    | Dr. Smith      |

**Problem:**
- DepartmentHead depends on Major, not StudentID

**3NF Solution:**

**Students Table:**
| StudentID | Name  | Major |
|-----------|-------|-------|
| 1         | Alice | CS    |

**Departments Table:**
| Major | DepartmentHead |
|-------|----------------|
| CS    | Dr. Smith      |

---

## Fourth Normal Form (4NF)
**Description:** 
Removes multi-valued dependencies where independent multi-valued facts exist in the same table.

- No multi-valued dependencies
- Independent multi-valued attributes must be separated

**Example (Before 4NF):**
| Teacher | Course | Language |
|---------|--------|----------|
| Alice   | Math   | English  |
| Alice   | Math   | French   |

**Problem:**
- Course and Language are independent facts

**4NF Solution:**

**Teacher-Course Table:**
| Teacher | Course |
|---------|--------|
| Alice   | Math   |

**Teacher-Language Table:**
| Teacher | Language |
|---------|----------|
| Alice   | English  |
| Alice   | French   |

---
## Fifth Normal Form (5NF)

**Description:** 
Removes join dependencies so that tables can be reconstructed from smaller tables without redundancy. 

- Handles complex join dependencies 
- Ensures lossless reconstruction using joins

**Example (Before 5NF):**
A company assigns employees to projects with specific roles.

| Employee | Project | Role |
|----------|---------|------|
| Alice    | Website | Designer |
| Alice    | App     | Designer |
| Bob      | Website | Developer |
| Bob      | App     | Developer |

**Problem:**
- The relationship between Employee, Project, and Role can be broken into smaller independent relationships.
- Storing all three together creates redundancy and duplication.

**5NF Solution:**

Split into 3 tables:

**Employee-Project Table:**
| Employee | Project |
|----------|---------|
| Alice    | Website |
| Alice    | App     |
| Bob      | Website |
| Bob      | App     |

**Employee-Role Table:**
| Employee | Role      |
|----------|-----------|
| Alice    | Designer  |
| Bob      | Developer |

**Project-Role Table:**
| Project | Role      |
|---------|-----------|
| Website | Designer  |
| Website | Developer |
| App     | Designer  |
| App     | Developer |
---

## Summary of Normal Forms

| Normal Form | Description |
|------------|-------------|
| 1NF | clean cells |
| 2NF | no partial dependency |
| 3NF | no indirect dependency |
| 4NF | no independent multi-lists |
| 5NF | perfect reconstruction using joins |

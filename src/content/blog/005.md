# 1. Naming Conventions

- Use `snake_case` for table and column names.
- Use plural names for tables (`users`, `employees`).
- Use singular names for columns (`user_id`, `role_id`).
- Use `id` as the primary key.
- Use `_id` for foreign keys.

Example

```sql
CREATE TABLE users (
    id SERIAL PRIMARY KEY,
    username TEXT,
    role_id INTEGER
);
```

---

# 2. Best Practices

- Prefer `UUID` for public identifiers.
- Normalize your database.
- Use `ENUM` for fixed values.
- Use `JSONB` only when flexibility is required.
- Validate and sanitize user input.
- Index frequently searched columns.
- Keep logs in dedicated tables.
- Include `created_at`, `updated_at`, and `deleted_at`.
- Use schemas for large applications.
- Prefer soft deletes when appropriate.

# 3. SQL Execution Order

Although we write SQL like this:

```sql
SELECT
FROM
JOIN
WHERE
GROUP BY
HAVING
ORDER BY
LIMIT
OFFSET
```

SQL actually executes in this order:

```text
FROM
JOIN
WHERE
GROUP BY
HAVING
SELECT
ORDER BY
LIMIT
OFFSET
```

Easy way to remember:

```text
Build → Filter → Group → Filter Groups → Select → Sort → Limit
```

# 10. GROUP BY

Groups rows together.

```sql
SELECT ur.name,
       COUNT(*)
FROM users u
JOIN user_roles ur
ON u.role_id = ur.id
GROUP BY ur.name;
```

Example

| Role | Count |
|------|------:|
| Admin | 2 |
| User | 5 |

---

# 11. HAVING

Filters grouped rows.

```sql
SELECT ur.name,
       COUNT(*)
FROM users u
JOIN user_roles ur
ON u.role_id = ur.id
GROUP BY ur.name
HAVING COUNT(*) >= 2;
```

Unlike `WHERE`, `HAVING` works on aggregate values.

# 13. Set Operators

Set operators combine the results of multiple `SELECT` statements.

Both queries must:

- Return the same number of columns.
- Have compatible data types.

---

## UNION

Combines results and removes duplicates.

```sql
SELECT username
FROM admins

UNION

SELECT username
FROM users;
```

Example

Admins

| username |
|----------|
| john |
| jane |

Users

| username |
|----------|
| jane |
| bob |

Result

| username |
|----------|
| john |
| jane |
| bob |

---

## UNION ALL

Keeps duplicates.

```sql
SELECT username
FROM admins

UNION ALL

SELECT username
FROM users;
```

Result

| username |
|----------|
| john |
| jane |
| jane |
| bob |

---

## INTERSECT

Returns only rows found in both queries.

```sql
SELECT username
FROM admins

INTERSECT

SELECT username
FROM users;
```

Result

| username |
|----------|
| jane |

---

## EXCEPT

Returns rows from the first query that don't exist in the second.

```sql
SELECT username
FROM admins

EXCEPT

SELECT username
FROM users;
```

Result

| username |
|----------|
| john |

---

### Summary

| Operator | Description |
|-----------|-------------|
| UNION | Combine unique rows |
| UNION ALL | Combine all rows |
| INTERSECT | Return common rows |
| EXCEPT | Return rows only in the first query |

## INNER JOIN

Returns matching rows.

```sql
SELECT u.username,
       r.name
FROM users u
INNER JOIN user_roles r
ON u.role_id = r.id;
```

---

## LEFT JOIN

Returns all rows from the left table.

```sql
SELECT u.username,
       r.name
FROM users u
LEFT JOIN user_roles r
ON u.role_id = r.id;
```

---

## RIGHT JOIN

Returns all rows from the right table.

```sql
SELECT u.username,
       r.name
FROM users u
RIGHT JOIN user_roles r
ON u.role_id = r.id;
```

---

## FULL OUTER JOIN

Returns every row from both tables.

```sql
SELECT u.username,
       r.name
FROM users u
FULL OUTER JOIN user_roles r
ON u.role_id = r.id;
```

---

## COALESCE

Replace NULL values.

```sql
SELECT
COALESCE(username,'No User')
FROM users;
```

# 16. Foreign Keys

```sql
CREATE TABLE users
(
    id SERIAL PRIMARY KEY,
    role_id INTEGER REFERENCES user_roles(id)
);
```

Actions

| Action | Description |
|----------|-------------|
| CASCADE | Propagate changes |
| SET NULL | Set foreign key to NULL |
| SET DEFAULT | Set default value |
| RESTRICT | Prevent deletion |
| NO ACTION | Check at transaction end |

Example

```sql
role_id INTEGER REFERENCES user_roles(id)
ON DELETE CASCADE;
```

# 17. Transactions & Concurrency

## Transactions

```sql
BEGIN;

UPDATE accounts
SET balance = balance - 100
WHERE id = 1;

UPDATE accounts
SET balance = balance + 100
WHERE id = 2;

COMMIT;
```

---

## SELECT FOR UPDATE

Locks rows while reading.

```sql
BEGIN;

SELECT *
FROM accounts
WHERE id = 1
FOR UPDATE;

UPDATE accounts
SET balance = balance - 100
WHERE id = 1;

COMMIT;
```

---

## Optimistic Locking

```sql
UPDATE accounts
SET balance = balance - 100,
    version = version + 1
WHERE id = 1
AND version = 5;
```

---

## SERIALIZABLE

Highest isolation level.

```sql
BEGIN;

SET TRANSACTION ISOLATION LEVEL SERIALIZABLE;

SELECT *
FROM accounts;

COMMIT;
```

---

## Advisory Locks

```sql
BEGIN;

SELECT pg_advisory_lock(12345);

UPDATE accounts
SET balance = balance - 100
WHERE id = 1;

SELECT pg_advisory_unlock(12345);

COMMIT;
```

---

## Concurrency Summary

| Method | Best For |
|----------|----------|
| Transactions | Normal updates |
| SELECT FOR UPDATE | Read → Modify → Write |
| Optimistic Locking | High concurrency |
| SERIALIZABLE | Maximum consistency |
| Advisory Locks | Cross-process locking |

## Core Concepts

- Rendering is **how and when HTML is generated** for a webpage.
- Hydration is the process where JavaScript **attaches interactivity** to already-rendered HTML.

> Rendering = creating the page  
> Hydration = making the page interactive

---

## Rendering Strategies

### 1. Client-Side Rendering (CSR)
- HTML is generated **in the browser using JavaScript**
- Initial HTML is mostly empty
- JavaScript builds the UI after loading

**Hydration:** ❌ Not applicable

**Flow:**
> Request → Empty HTML → Load JS → Render UI

---

### 2. Server-Side Rendering (SSR)
- HTML is generated **on the server for every request**
- Browser receives fully rendered HTML

**Hydration:** Happens in the browser (for client components)

**Flow:**
> Request → Server renders HTML → Browser receives HTML → Hydration → Interactive UI

---

### 3. Static Site Generation (SSG)
- HTML is generated **at build time**
- Served as static files

**Hydration:** Happens in the browser (for client components)

**Flow:**
> Build → Static HTML → Request → Serve HTML → Hydration → Interactive UI

---

### 4. Incremental Static Regeneration (ISR)
- Similar to SSG, but pages can be **updated after deployment**
- Pages are regenerated in the background using caching + revalidation

**Hydration:** Happens in the browser (for client components)

**Flow:**
> Build → Static HTML → Request → Serve HTML → Background revalidation → Hydration

---

### 5. Islands Architecture
- Page is split into independent interactive “islands”
- Each island hydrates separately

**Hydration:** Partial — each island hydrates independently, not the whole page.

---

### 6. Partial Hydration
- Only **specific parts of a page** are hydrated
- Non-interactive sections remain static HTML

**Hydration:** Partial — only interactive components are hydrated, static parts are skipped.

---

### 7. Server Components (RSC)
- Components that run **only on the server**
- They are never sent as JavaScript to the browser
- They do **not hydrate**

**Hydration:** None — Server Components do not hydrate because no JavaScript is sent to the browser.

---

### Key Differences Summary
| Concept           | Where it runs    | JS sent? | Hydration |
| ----------------- | ---------------- | -------- | --------- |
| CSR               | Browser          | Yes      | No        |
| SSR               | Server + Browser | Yes      | Yes       |
| SSG               | Build + Browser  | Yes      | Yes       |
| ISR               | Server + Browser | Yes      | Yes       |
| Islands           | Mixed            | Partial  | Partial   |
| Partial Hydration | Browser          | Less JS  | Partial   |
| Server Components | Server only      | No       | No        |
